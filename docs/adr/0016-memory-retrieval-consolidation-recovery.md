# ADR-0016: Retrieval, consolidation, corrections and restart recovery

**Status:** Accepted (2026-10-23). Implemented and tested offline and against a real local PostgreSQL in a throwaway schema. Spoken/live behaviour with Gemini is unverified. The document-RAG deferral in decision 9 is superseded by [ADR-0017](0017-document-rag.md); the rest of this decision still stands.
**Context:** ADR-0015 made meetings automatic and meeting-scoped, but an audit found seven defects: (1) SESSION-tier notes lived only in `InMemoryMeetingMemory` and disappeared on exit; (2) persisted records used `action` while live notes used `action_item`, and recall compared across the two vocabularies; (3) a correction created a disconnected row unless a caller supplied `supersedes_id`; (4) retrieval was full-text search plus recency, with no kind/time filters, status or kind weighting, diversity or conflict handling; (5) a proposal could be extracted with kind `decision`; (6) restart recovery summarized missing summaries but never distinguished a completed meeting from an abandoned one; (7) the startup block had no dates or meeting numbers, no open-action section and no conflict labels.

**Decision:**

1. **One kind vocabulary.** `memory/kinds.py` owns canonical persisted kinds and the explicit `action_item -> action`, `open_question/proposal -> note` translations. `MemoryItem` accepts legacy spellings but stores canonical kinds. New note kind `proposal` is used only in live minutes and maps to a `note` record with `metadata.note_kind`.
2. **Wording is classified, not inferred as truth.** `memory/claims.py` labels assertion, preference, decision, proposal, action, question, hypothetical and correction. A proposal or hypothetical can never keep the `decision` kind; it becomes a tentative `note` candidate. An assertion the extractor labelled `decision` keeps that kind (the model saw context the sentence lacks) but remains a candidate.
3. **Session notes are durable.** `AutoMemory` writes the live note and a candidate record in the same turn-observation task. The live copy keeps the meeting responsive; the durable copy survives exit.
4. **Corrections link explicitly or stay flagged.** `MemoryService.remember(kind="correction")` resolves a target by token overlap plus FTS. A clear winner is superseded (new row first, then the old row is marked with `superseded_by`); an ambiguous case supersedes nothing and records `correction_candidates` and `possible_conflict`. A model-proposed `corrects` reference is resolved against rows Tara actually holds. History is never deleted.
5. **Conservative consolidation.** Only same-kind durable records with token Jaccard ≥ 0.9 merge. Numbers and dates are significant tokens. Consolidation is bounded (`consolidate(scope, limit=200)`), runs once per start in a background task, and records `duplicate_of` on the superseded copy. Similar-but-different claims are flagged, not merged.
6. **Hybrid retrieval without an embedding dependency.** PostgreSQL full-text search (with the existing any-content-word fallback) proposes candidates; `memory/retrieval.py` re-ranks them with rarity-weighted keyword coverage, phrase match, status, kind, a 45-day recency half-life, conflict penalty and near-duplicate diversity. Time and kind filters are applied in the store before ranking. If a filter yields no keyword candidates, the newest records in that window are returned and labelled `recent`.
7. **Startup selection is ordered, not just recent.** One summary per meeting first, then corrections, decisions, open action items, other confirmed items, other candidates, and at most three transcript chunks. Meeting number and date are rendered when known; candidates are labelled unconfirmed and tentative proposals are labelled "proposal, not agreed".
8. **Recovery distinguishes interrupted from completed.** `meeting_sessions` gains `interrupted`, `owner_pid` and `owner_host` (migration 005). At start, open sessions from a dead process are closed at their last activity and marked interrupted. A session owned by another live process on the same host is left alone.
9. **Document RAG is deferred.** The existing `KnowledgeProvider` has no ingestion, chunk storage, scope or deletion path. Completing conversational memory first is higher value than a half-built document pipeline; the gap is stated in the operations doc.

**What this deliberately does not do:** no embeddings/pgvector, no Redis, no new infrastructure, no automatic truth promotion from repetition alone (a repeated proposal stays tentative), and no claim of measured retrieval quality or latency.

**Consequences:** More rows are written per meeting (one per detected note in addition to transcript chunks and digest facts), so dedupe and expiry matter. Near-duplicate detection depends on shared words; a paraphrase with no shared content words is stored as a new record and flagged only if a keyword match exists. Recovery assumes one application process per section per host; a row from another host cannot be liveness-checked. Ranking weights are starting values that need a labelled evaluation set before tuning.
