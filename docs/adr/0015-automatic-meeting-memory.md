# ADR-0015: Automatic, meeting-scoped memory

**Status:** Accepted (2026-10-21). Implemented and tested offline and against real PostgreSQL in a temporary schema; the spoken behaviour is not yet verified. Retrieval, consolidation, corrections and recovery were extended by [ADR-0016](0016-memory-retrieval-consolidation-recovery.md).
**Context:** Memory v1 saved only what a participant explicitly asked to remember, which failed in real use: people do not say "remember this", and saves were refused when the transcript lagged. Mainstream assistants keep memory without being asked: ChatGPT keeps explicit saved memories plus automatic reference to past chats, and reports describe Claude keeping separate memory per project. Sources are in `docs/research/SOURCES.md`. The owner runs everything on one laptop with local PostgreSQL, so storage is cheap, and wants meetings not to leak into each other.

**Decision:**
1. **Layers.** Working memory (in process, short-term) stays as is. New durable layers in `memory_records`: `episode` (verbatim transcript chunks, written every `TARA_CHUNK_TURNS` turns), `summary` (generated by the text model), and extracted facts, decisions and actions stored as unconfirmed candidates. Explicit "remember this" still stores confirmed memory.
2. **Meeting scope.** A `MemoryScope` may carry a `meeting_id` (a slug of the meeting name). Reads and writes inside a scope stay in that meeting. The same name continues a meeting; a new name starts a separate one. Cross-meeting recall does not exist by default.
3. **Verification.** The text model proposes facts only with a verbatim quote that must appear in the transcript. Sensitive lines are replaced by a placeholder before storing or sending to a model. A transcript statement stays a claim: facts are candidates and are labelled unconfirmed in the startup block.
4. **Retention.** Episodes expire after `TARA_EPISODE_RETENTION_DAYS` (90), unconfirmed facts after `TARA_FACT_RETENTION_DAYS` (180); expired rows are purged. Summaries and confirmed items do not expire.
5. **Retrieval.** Still PostgreSQL full-text search plus recency (ADR-0012). The startup block puts summaries first, then facts, then at most three transcript chunks. A broad question with no keyword match falls back to the newest items.

6. **Sections and numbered meetings.** The scope's `meeting_id` is the section (a chat). Each run is a numbered meeting inside it, recorded in `meeting_sessions` (migration 003) with start and end times; records link to a meeting by `session_id`. At startup Tara is told which meeting this is and gets a dated list of earlier meetings with summaries; tools `list_meetings` and `meeting_lookup` answer "last meeting", "meeting two" and "which meetings have we had". Rows with no section stay global.

7. **Summaries are best effort and repaired later.** The summary comes from a text model with its own setting (`TARA_RECORDER_MODEL`) and timeout. If it fails, the transcript chunks are still stored, and the next start summarizes any earlier meeting that has chunks but no summary.

8. **Editing memory.** A meeting can be deleted on request. Unimportant meetings go at once; important ones (confirmed items, decisions or actions, several key facts, or a long discussion) need a question and a spoken yes that the code checks, not the model. Deletion is soft. A stored memory can be corrected with `update_memory`, which supersedes the old one and keeps it as history.
9. **Failures are spoken.** Failed tools tell the model to explain, the engine prompts the model if it stays silent after a failure, and the demo prints problems on screen.

**Not decided here:** pgvector or embeddings. Semantic ("meaning") search is a later step that needs an evaluation set first (ADR-0009 stays the design). Until then, recall is keyword plus recency, and the summary and extracted facts carry most of the meaning.

**Consequences:** Every meeting is stored without the participant doing anything, so the disclosure and retention rules matter more (docs/architecture/SECURITY_AND_PRIVACY.md). A model call happens at checkpoints and at the end, never on the audio path. Quality of extracted facts is unmeasured.
